## Overview

Aligned the terraform-provider-mica on FlashBlade® REST API 2.23 (Purity//FB 4.7+). Added Workload as a first-class resource + data source, surfaced Resiliency Group topology through read-only data sources, and propagated the `workload` field across the six policy/file-system resources that gained it in API 2.23. The bulk of the implementation had already landed on the `test/api-upgrade-2.23` branch (~167 files, ~7000 insertions) via the `api-diff` / `api-upgrade` skills before the GSD milestone was formalised — this milestone therefore acted as a **retro + finalisation** wrapper that validated the work end-to-end, regenerated the Pulumi bridge schema, refreshed the API coverage counters, and shipped the release.

## Milestone Summary

**Key Decisions:**

- **Retro framing** — Most of the implementation was already on `test/api-upgrade-2.23` when the milestone was formalised. Decision: capture 20 already-shipped REQ-IDs as traceability rather than re-implement; keep 13 active REQ-IDs (VALID-* + RELEASE-*) for the finalisation tail. Saved a planning rewrite and kept the existing commit history intact.
- **Phase 60 strict serialisation** — 5 waves of 1 plan each (preflight → rebase/PR → merge → tag/release → baseline/archive). Release operations cannot parallelise; each step gates the next via destructive remote action.
- **VALID-04 blocking checkpoint at top of 60-01** — No release work proceeded until par5 + pa7 acceptance was operator-signed-off in `59-HUMAN-UAT.md`. Prevented shipping un-validated against real arrays.
- **Squash merge** for PR #16 — collapsed 45 feature commits into a single `feat(v2.23.0): …` commit on `main` for a clean release history.
- **Tag on `f85ea8d`** (HEAD with 60-03 planning docs) rather than the bare squash commit (`3fd485d`) — keeps the milestone planning trace in the release SHA range.

**Issues Resolved:**

- API version bump 2.22 → 2.23 across provider, client, mock handlers, examples, and API references (commit `9a9715b` + follow-ups).
- New resource `flashblade_workload` (R + DS) + new data sources `flashblade_resiliency_group`, `flashblade_resiliency_group_member`.
- Schema v1 migrations on 6 existing resources adding the `workload` field: file_system, file_system_export, nfs_export_policy, smb_client_policy, smb_share_policy, qos_policy. qos_policy also gained a computed `context` field; its upgrader was realigned on the canonical chain pattern (commit `5ab258a`).
- Pulumi bridge regenerated for the 4 new tokens + 6 schema-v1 deltas. `make tfgen` is idempotent; `git diff --exit-code -- pulumi/` returns 0.
- Branch shipped via `numberly/terraform-provider-mica` PR #16 → `main` → tag `v2.23.0` → GoReleaser signed release (cosign + GPG).

**Issues Deferred:**

- Pulumi SDK regeneration / private release for `pulumi-2.23.0` — split into a dedicated milestone so this one ships the TF provider clean.
- Workload metadata / label / tag CRUD — API 2.23 does not yet expose these as mutable; revisit when surfaced.
- Resiliency group CRUD — API 2.23 is read-only on these endpoints; data sources only.
- Acceptance tests integrated into CI — still operator-driven against par5 + pa7. Tracked for a future hardening milestone.

**Technical Debt Incurred:**

- `59-04-acceptance-live` was operator-signed-off rather than executor-driven. The HCL fixtures under `examples/acceptance/api-2-23/` were not authored by the GSD planner because acceptance was run from existing examples / pre-existing operator workflow. If a future milestone needs reproducible CI acceptance, the fixtures must be authored explicitly.
- The retro framing means 20 REQ-IDs map to commits made before GSD was tracking the milestone. Traceability is captured in `59-01-RETRO.md`; the link is by commit SHA + Serena symbol lookup rather than by GSD plan execution log.
